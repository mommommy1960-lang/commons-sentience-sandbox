# Maya Node Founding Review Workflow

## User promise

A human-delivered design review focused on consent, permission boundaries, authority escalation, auditability, revocation, and fail-closed behavior.

## Review steps

1. State the design's intended purpose.
2. List every requested capability and its authority boundary.
3. Check whether authority can expand without fresh approval.
4. Check instruction freshness, attribution, and revocation.
5. Identify unknown external actions and fail-closed behavior.
6. Run one bounded adversarial test.
7. Record evidence, uncertainty, and recommended correction.
8. Deliver the report and invite one correction round.

## Explicit limits

This is not certification, legal advice, penetration testing, or a production-readiness approval. The reviewer does not operate the client's system or authorize external actions.

## Completion criteria

- intake complete;
- boundary map complete;
- one adversarial test documented;
- report delivered;
- client correction or disagreement recorded;
- no claim exceeds the evidence.
