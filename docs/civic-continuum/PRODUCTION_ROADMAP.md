# Civic Continuum production roadmap

## Operating rule

Reality first. Anomaly second. Follow through.

Software comes before hardware. Revenue comes before discretionary spending. No procurement, fabrication, manufacturing, paid engineering, legal commitment, or sale launch occurs without separate written approval.

## Phase 0: inventory and truth layer

1. Preserve the existing `main` branches.
2. Keep the master portfolio PR draft until the user reviews it.
3. Build a source register linking each product claim to a Word or Zenodo source.
4. Label each concept PRODUCT, SERVICE, PROTOTYPE, RESEARCH, PUBLISHING, or HOLD.
5. Record unresolved evidence, rights, safety, and funding blockers.

Exit evidence: source register, claim-boundary document, repository map, and decision log.

## Phase 1: first revenue

### Maya Node

Package the founding review as a clear service page, intake form, scope template, report template, adversarial-test template, and payment-ready workflow. Verify the live site and payment path before making availability claims.

### Governance review products

Create one sample systems-accountability review using anonymized or consented material. Define what is included, what is excluded, turnaround, revision policy, and escalation to counsel.

Exit evidence: a tested delivery checklist, a sample redacted report, and approved pricing.

## Phase 2: software product

### Civic Continuum Companion

1. Repair and run the unit tests.
2. Make the safety-test workflow execute real jobs instead of silently producing no jobs.
3. Resolve the missing secret or remove the dependency from tests that should be offline.
4. Verify pause, resume, step budgets, terminal-job protection, audit tamper detection, permission boundaries, emergency freeze, and data minimization.
5. Produce a local demo and a plain-language limitation statement.
6. Run a supervised pilot with no autonomous control of critical systems.

Exit evidence: reproducible test run, security review, privacy review, pilot protocol, and a working demo.

## Phase 3: physical prototype

### Crowned Coil

Complete requirements, animal-safety constraints, drawings, materials, dimensions, use limits, cleaning requirements, and failure modes before requesting quotes. Build one prototype only after written approval. Test under supervision and document failures before considering a founder batch.

### Companion hardware

Only after the software boundary is stable, define a phone-connected enclosure or wearable interface. The first hardware target is a safe demonstrator, not a general-purpose robot or android.

Exit evidence: test report, hazards log, user instructions, and approval for any production spend.

## Phase 4: larger programs

Cask & Crunch, C.A.R.E., Academy expansion, orbital servicing, Aurora, Flux Drive, QCV, and MPRS remain sequenced behind evidence and resources. Their first deliverables should be compliant software, education, simulation, or documentation—not unsupported claims of physical realization.

## Release gate

No public launch until the workstream has:

- a named owner and scope;
- a source register;
- a claim-boundary statement;
- a reproducible test or review checklist;
- a risk and failure log;
- a rights and privacy check;
- a price or funding decision approved by the user;
- and a rollback or correction path.
