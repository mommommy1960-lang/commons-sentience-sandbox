## What a reviewer can see

The repository shows the path from an initial problem to a bounded claim, a paper specification, a software or tabletop prototype, an independent test, and—only if the evidence supports it—a later product or pilot.

Each project is labeled separately as:

- concept
- paper specification
- software prototype
- bench or tabletop prototype
- independent validation
- supervised pilot
- market-ready product

A document, image, simulation, timestamp, or DOI establishes provenance or communication. It does not by itself establish physical feasibility, safety, certification, legal enforceability, patent rights, or market demand.

## Current operating rule

Build a small, honest version of Civic Continuum today. Measure it. Preserve failures. Correct it. Expand only when evidence, safety, resources, and community feedback justify the next stage.

## Public/private boundary

Public materials include mission, requirements, evidence labels, test status, limitations, sanitized product briefs, and citations.

Private materials remain private: credentials, keys, personal information, supplier quotes, NDA language, unreleased drawings, detailed security architecture, medical or biological procedures, and patent-sensitive implementation details.

## Current proof cycle

1. Repair offline tests and preserve the failure record.
2. Make the Consent Token demonstrator usable.
3. Make one Systems Accountability Engineering module teachable.
4. Make Maya Node fulfillment repeatable.
5. Publish evidence, failures, and limitations.
6. Build the private SAGE/MAYA demonstration.
7. Advance physical concepts only through safe, conventional, independently reviewable gates.

## Claim boundary

The public repository does not claim sentience, autonomous authority, validated propulsion, an operational interstellar vessel, medical readiness, or production readiness where those claims have not been independently demonstrated.
